## 2. 背景与问题

原脚本共 1,438 行，界面、配置、批量调度、PDF 读取、银行规则、AI 调用、校验和 Excel 输出集中在同一个文件中。继续追加银行规则会使修改范围越来越大，也难以单独验证某一项功能。

本次检查的 13 份民生银行对账单共 27 页，版式一致，包含 404 笔交易。所有 PDF 均有可提取文字，但没有能被默认表格识别直接识别的完整框线。原脚本只为华夏银行提供专用文字规则，同时把“存在可提取文字”误当作“不需要 AI”的条件，因此这批文件在默认模式下会全部失败。

试解析已经确认：采用页面固定栏目位置读取，可以完整取得 404 笔交易；每份文件的笔数、借方合计和贷方合计均与页尾一致，连续余额无差异，必填字段无缺失。2025 年 10 月和 11 月是零交易月份。

## 3. 目标

本次重构实现以下目标：

1. 把原单文件整体拆成职责清晰、可分别测试的模块。
2. 长期稳定支持当前版式的民生银行单位账户对账单。
3. 保留华夏银行规则、普通表格读取和断点续传能力，并把网络及本地 AI 统一改为可配置的通用接口。
4. 建立统一的读取顺序、统一流水字段和统一核对规则。
5. 批量处理中隔离问题文件，不让未通过核对的数据混入合格明细。
6. 生成一个 Excel，包含“流水明细”和“提取汇总”两张工作表。
7. 保留来源文件和来源页码，使每一笔数据均可回查。
8. 保存结果时不覆盖历史文件。

## 4. 非目标

本次不包含以下事项：

1. 不制作 Windows 可执行程序。
2. 不承诺支持尚未取得真实样本的所有银行和所有版式。
3. 不修改、重命名或重建任何原始 PDF。
4. 不让 AI 结果绕过笔数、金额和余额核对。
5. 不在证据不足时自动补齐、猜测或删除交易数据。
6. 本次不直接适配各厂商互不兼容的专有调用格式；非 OpenAI 兼容接口需另加适配器。

## 5. 项目结构

新项目采用以下结构：

```text
PDF表格提取工具\
├─ main.py                         启动入口
├─ app\
│  ├─ ui\                          界面、按钮、进度和日志
│  ├─ config\                      通用模型配置、保存和兼容迁移
│  ├─ models\                      统一流水、文件结果和核对结果
│  ├─ extractors\                  各种 PDF 读取方式
│  │  ├─ generic_table.py          普通表格读取
│  │  ├─ minsheng.py               民生银行固定栏目读取
│  │  ├─ huaxia.py                 华夏银行文字规则
│  │  └─ ai_vision.py              通用视觉模型接口
│  ├─ routing\                     银行识别和读取顺序
│  ├─ validators\                  笔数、金额、余额和必填字段核对
│  ├─ services\                    单文件处理、批量处理和失败隔离
│  └─ exporters\                   Excel 输出与格式设置
├─ tests\                          自动测试
└─ docs\                           设计说明和实施计划
```

模块之间只能通过统一的数据对象传递结果。界面不直接解析 PDF，读取模块不直接生成 Excel，核对模块不负责修改流水。

## 6. 统一数据结构

每笔流水统一包含以下字段：

1. 交易日期时间
2. 摘要
3. 凭证类型
4. 凭证号码
5. 借方发生额
6. 贷方发生额
7. 账户余额
8. 流水号
9. 对方户名或账号
10. 对方行名
11. 银行名称
12. 本方账号
13. 对账期间
14. 来源文件
15. 来源页码
16. 读取方式

账号、凭证号码和流水号始终按文字保存。借方发生额、贷方发生额和账户余额使用精确的小数金额，不用近似数计算。

每份 PDF 还要产生一个文件级结果，记录文件名、银行、账号、期间、页数、声明笔数、实际笔数、声明借贷合计、实际借贷合计、余额检查结果、最终状态和失败原因。

## 7. 读取顺序

系统按以下顺序处理每份 PDF：

1. 普通表格读取。
2. 民生银行专用规则。
3. 华夏银行专用规则。
4. AI 视觉识别。

“PDF 有文字”只说明可以尝试文字读取，不再作为禁止 AI 兜底的条件。只有前一种方式未取得可核对结果时，才进入下一种方式。

每种读取方式返回统一结果，不直接决定文件是否合格。最终是否进入流水明细只由核对模块决定。

## 8. 民生银行读取规则

民生银行对账单使用页面上的固定栏目位置读取，不依赖表格框线，也不根据空格猜测字段。

处理步骤如下：

1. 识别“单位账户对账单”、客户账号、起止日期和固定表头。
2. 以交易日期所在位置确定每笔交易的开始位置。
3. 以十个固定栏目的横向范围归集文字。
4. 把同一笔交易中换行的时间、流水号、对方户名或账号、对方行名重新拼接。
5. 排除页眉、固定表头、页尾合计、打印信息、印章和二维码。
6. 为每笔交易记录来源文件和来源页码。
7. 从页尾读取声明笔数、借方合计和贷方合计，用于后续核对。

固定栏目参数集中管理，不散落在界面或批量处理代码中。后续出现新版式时，可以增加新的版式参数或新的读取器，不修改现有稳定规则。

## 9. 核对规则

每份文件必须通过以下四类核对：

1. 笔数核对：实际提取笔数等于对账单声明笔数。
2. 金额核对：实际借方合计、贷方合计分别等于对账单声明金额。
3. 连续余额核对：从第二笔开始，上一笔余额减借方发生额加贷方发生额等于本笔余额。
4. 必填字段核对：交易时间、借方发生额、贷方发生额、账户余额和流水号可以按规则解析。

零交易文件在声明笔数和借贷合计均为零时，状态记为“零交易通过”。零交易文件不产生虚假明细，但必须进入“提取汇总”。

任一核对不通过，文件状态记为“核对失败”。失败文件的数据不得进入“流水明细”。失败原因必须明确到具体核对项目，并保留声明值、实际值和差异。

## 10. 批量处理

用户选择一个文件夹后，系统读取该文件夹及其子文件夹中的全部 PDF。

批量处理遵循以下规则：

1. 单个文件失败不影响其他文件继续处理。
2. 文件按对账期间排序，不能按文件名字面顺序排序。
3. 明细按对账期间、交易时间、来源文件和来源页码形成稳定顺序。
4. 合格文件进入流水明细。
5. 零交易文件只进入提取汇总。
6. 问题文件不进入流水明细，在提取汇总中标红并说明原因。
7. 每个文件的处理状态均在界面日志中显示。

## 11. AI 兜底与断点续传

AI 只处理普通表格和银行专用规则均无法取得可核对结果的文件。

网络模式不再写死百炼、千问、固定域名或固定模型。在线服务与本地服务使用同一套通用配置，用户填写：

1. 接口地址：允许填写服务基础地址或完整的聊天接口地址。
2. API Key：使用遮挡输入；允许本地服务留空；不得写入日志或 Excel。
3. 模型名称：完整传递用户填写的名称，不在代码中限制模型清单。

通用接口采用 OpenAI 兼容的聊天请求格式，并通过图片消息传入 PDF 页面。所选模型必须支持图片输入；纯文字模型即使接口连通，也不能用于 PDF 图片识别。连接测试需要分别报告“接口连通”“模型可用”和“图片能力可用”，不能只因模型列表可读取就显示全部通过。

接口地址规范化只能补全通用路径，不能替换用户填写的域名、供应商或模型。既要兼容在线服务，也要兼容 LM Studio 等无需 API Key 的本地服务。

重构后继续读取当前用户配置目录。旧版百炼和本地模型设置在首次启动时迁移为通用配置，不要求用户重新输入仍然有效的内容。API Key 不以明文写入主配置文件，也不在异常信息中回显。

AI 结果必须转换为统一流水结构，并通过与常规读取相同的核对。接口返回成功、页面识别成功或生成了临时数据，都不能代替最终核对。

断点续传记录必须包含文件身份、已完成页码、统一表头和已取得数据。只有临时记录与当前文件匹配时才允许继续，避免把其他文件的临时结果接到当前文件。

## 12. Excel 输出

输出文件保存到用户所选 PDF 文件夹下的：

`提取结果\银行流水汇总_YYYYMMDD_HHMMSS.xlsx`

文件名带生成时间，不覆盖历史结果。

“流水明细”工作表包含统一流水字段，设置筛选、冻结首行、合适列宽、日期时间格式和金额格式。账号、凭证号码、流水号强制使用文字格式。

“提取汇总”工作表逐份展示文件状态、银行、账号、期间、页数、声明笔数、实际笔数、声明借贷合计、实际借贷合计、余额检查、读取方式和失败原因。核对失败行使用醒目的红色提示，零交易文件显示“零交易通过”。

## 15. 测试与验收

自动测试至少覆盖：

1. 民生银行零交易、单页、多页、长摘要、字段换行和连续余额。
2. 华夏银行现有文字规则。
3. 普通表格读取成功和失败。
4. 读取方式依次降级到 AI。
5. 通用模型接口填写基础地址、完整地址、空 API Key 和不同模型名称。
6. 接口连通但模型不存在、模型不支持图片、AI 返回空内容、列数不一致、网络失败和断点续传。
7. 笔数、金额、余额和必填字段核对失败。
8. 问题文件隔离。
9. 文件期间排序和明细排序。
10. Excel 标识字段的文字格式。
11. 历史结果不被覆盖。

AI 路由测试使用模拟响应，不产生无必要的接口费用。测试还要确认代码中不存在百炼域名、千问模型名或其他在线供应商的强制默认值。
