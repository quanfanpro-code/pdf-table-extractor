# PDF 表格提取工具模块化重构实施计划

> **供智能执行者使用：** 必须使用 `executing-plans` 在当前任务中逐项实施；每个任务均按复选框跟踪。当前任务未获准委派，不使用子代理。

**目标：** 把 1,438 行单文件工具重构为可分别测试的模块，稳定读取民生银行对账单，保留华夏银行和 AI 兜底，并输出可追溯、经过核对的双工作表 Excel。

**架构：** 使用少量职责明确的 Python 模块：统一数据对象、配置、读取器、核对、批量服务、Excel 输出和界面。读取器只负责取得数据，核对模块是进入明细表的唯一门禁，界面只负责收集输入和展示进度。

**技术栈：** Windows 11、Python 3.14、pdfplumber 0.11.10、openpyxl 3.1.5、customtkinter 6.0.0、pypdfium2 5.13.0、requests 2.34.2、Pillow 12.3.0、pytest 9.1.1。

## 全局约束

- 只考虑 Windows，不做 macOS 或 Linux 兼容适配。
- 所有面向用户的文字、Markdown 文档和代码注释使用中文。
- 不增加现有环境之外的新依赖；Excel 直接使用 openpyxl，不再通过 pandas 中转。
- 修改任何现有文件前，先备份到 `C:\Users\27651\Documents\BackUp\PDF表格提取工具_时间戳\` 并核对 SHA256。
- 不修改任何原始 PDF；真实验收前后逐文件核对 SHA256。
- 不使用 `rm -rf`，不执行不可恢复删除。
- 不把百炼域名、千问模型名或其他在线供应商写成强制默认值。
- 通用模型接口只承诺 OpenAI 兼容格式；模型必须支持图片输入。
- API Key 不写入日志、Excel 或主配置文件。
- 问题文件不得进入“流水明细”，必须在“提取汇总”中明确记录原因。
- 保存到 `提取结果\银行流水汇总_YYYYMMDD_HHMMSS.xlsx`，不得覆盖历史结果。
- 原脚本只有在新版本全部验收通过后才改名为 `自动提取PDF中的表格_旧版_停用.py`。
