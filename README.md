# 📄 PDF 银行对账单整理工具

> 🏦 把一堆银行对账单 PDF 文件，自动变成一份整整齐齐、能追溯来源的 Excel 表格，并且帮你逐份核对有没有读错、读漏。

---

## 本次新增检查（2026年9月8日）

选择PDF文件或目录后，以下检查随批量提取自动运行，不用逐份确认。

### 期初、期末余额

程序读取原对账单独立列示的期初、期末余额，核对期初余额减支出加收入是否等于期末余额，并分别核对第一笔、最后一笔交易后的余额。这里沿用现有银行流水字段的含义，借方为支出、贷方为收入。

只有一笔交易也会核对；零交易时核对期初和期末是否一致。由交易推算出的余额不当成原件控制数，资料缺失时明确写出哪些检查没做。已有解析取得的控制数会保留，后续换读取方式时不能因为控制数丢失而变成通过。

“提取汇总”增加原件余额、来源页、明确账期、各项差额和检查结果。由于控制余额不符而未进入“流水明细”的交易，会另放到“待核查流水”，供回看原件。

### 多期对账单衔接

同银行、完整账号、同币种的文件，按原件明确注明的起止期间检查中间缺期、期间重叠，以及相邻期末与期初余额是否一致。结果放到“期间衔接检查”。

只检查本次提供的资料，不假定每批都是全年。第一笔和最后一笔交易日期不冒充对账期间；没有交易的日子不等于缺期。账号遮盖、币种或账期不清楚时注明未检查，不强行串接。重叠文件只提示，不自动删除流水。

缺期、重叠时仍输出已提取的流水和检查结果，不使整批停止。单份文件原有笔数、合计检查通过，也不代表新增控制余额或批次衔接项目全部完成，请同时查看新增结果。

## 🌟 这个工具是干什么的？

想象一下这样的场景：你手头有几十份银行发来的对账单 PDF 文件，每份里面都是一页一页的银行流水表格。你想把这些流水全部汇总到一张 Excel 表里做账、核对或者归档。

如果靠人手抄，一份对账单可能有几百行，眼睛都要看花，还容易抄错。😵

这个工具就是来替你干这个苦活儿的：

- 📂 你只要告诉它 PDF 在哪里（选几个文件，或者选整个文件夹）
- 🤖 它就一份一份地自动读取里面的流水表格
- ✅ 每读完一份，它还会**自动核对**：账单上自己写的总笔数、总金额，和它实际读出来的对不对得上
- 📊 最后汇总生成一份漂亮的 Excel，哪些读成功了、哪些失败了，一目了然

简单说：**给它一堆 PDF，还你一张核对过的 Excel。** 🎁

## ✨ 它有哪些本事？

- 📁 **批量处理**：一次可以处理几百份 PDF，不用一份一份点
- 🏦 **认识多家银行**：内置了民生银行、华夏银行的专用读取方式，其他银行的常见表格格式也能认
- 👁️ **会用"眼睛"**：遇到排版奇怪的 PDF，可以调用视觉大模型（一种能"看懂图片"的人工智能）把页面当图片来认，作为兜底手段
- ✅ **自动对账**：不是读出来就完事，它会核对账单上声明的笔数、借方合计、贷方合计，还会检查每一笔的余额是否前后接得上
- 📊 **结果可追溯**：Excel 里每一行流水都标注了它来自哪个 PDF 文件、第几页，出问题能马上查回去
- 🎨 **界面友好**：有图形化窗口，不用敲命令，还能切换浅色/深色皮肤
- 💾 **记忆设置**：你填过的模型配置会自动保存，下次打开不用重填

## ⚙️ 程序内部是怎么干活的？（运行逻辑）

点下"开始整理"之后，程序对**每一份 PDF** 都做一遍下面这套流程：

### 第一步：轮番尝试读取 🔄

程序手里有好几种"读表格的方法"，它会按顺序一个一个试，就像开锁时挨个试钥匙 🔑：

1. 🗂️ **普通表格读取**：先试试最常见的表格排版能不能认出来
2. 🏦 **民生银行专用读取**：如果文件是民生银行的格式，用专门定制的读法
3. 🏦 **华夏银行专用读取**：同理，华夏银行也有自己的专用读法
4. 👁️ **视觉模型兜底**：前面都失败了，就把 PDF 每一页转成图片，发给人工智能，请它把看到的表格"抄"下来

> ⚠️ 如果你打开了"强制使用视觉模型"开关，前三把钥匙直接跳过，只用人工智能看图。

### 第二步：每读出一种，立刻核对 ✅

**关键设计：不是读出来就算成功，核对通过才算数。**

每用一种方法读完，程序马上做这些检查：

- 🔢 **笔数核对**：账单上写着"本期共 X 笔"，程序数数自己实际读出来几笔，对不上就是有问题
- 💰 **借方合计核对**：账单上写的借方总金额 vs 程序把每一笔借方加起来的金额
- 💰 **贷方合计核对**：同理核对贷方
- 🔗 **连续余额核对**：银行流水有个特点——上一笔的余额，减去这笔支出、加上这笔收入，应该正好等于这笔的余额。程序逐笔验证这个链条有没有断，断了说明中间可能读漏或读错了
- 🔖 **流水号检查**：每一笔都应该有流水号，空了就报出来

### 第三步：根据核对结果决定去留 🚦

- ✅ **核对通过** → 这份文件的数据被采纳，换下一份
- ❌ **核对失败** → **不放弃**！记下失败原因，换下一把"钥匙"重新读、重新核对
- 😢 **所有方法都失败** → 这份文件被标记为"核对失败"，原因写进日志和 Excel，**但不影响其他文件继续处理**（一份失败不会拖垮整批）

### 第四步：汇总导出 📊

所有文件处理完后：

- 只有**核对通过**（包括账单本身就是零交易的）的流水，才会进入 Excel 的明细表——**没核对上的数据绝不混进去**，防止脏数据污染你的账
- 明细按交易时间先后排好序
- 在你选的文件夹下新建一个叫 **"提取结果"** 的子文件夹，把 Excel 存进去

## 📊 生成的 Excel 长什么样？

文件名类似 `银行流水汇总_20260825_193000.xlsx`（带日期时间，**永远不会覆盖旧文件**，同一秒生成两份就自动加序号）。

打开后有三个常设工作表，另按结果增加待核查流水：

### 📋 第一个表：流水明细
- 所有核对通过的流水，一行一笔，按时间排好
- 包含：银行名称、账号、交易时间、摘要、借方/贷方金额、账户余额、流水号、对方户名等
- 👀 特别注意最后几列：**来源文件** 和 **来源页码**——每一行都能查回它出自哪份 PDF 的第几页，方便抽查复核 🔍

### 📈 第二个表：提取汇总
- 一份 PDF 一行，是整场处理的"成绩单"
- 列出每份文件的状态、银行、账号、账单日期范围、页数、声明笔数 vs 实际笔数、声明金额 vs 实际金额、余额链条是否完整
- 🟥 **红色行** = 核对失败的文件，“失败原因”列写明了原因
- 🟨 **黄色行** = 账单本身一笔交易都没有（零交易），属正常通过
- ⬜ 普通行 = 原有项目核对通过，新增项目是否完整执行另看各项结果

### 第三个表 期间衔接检查

列出同账户同币种文件之间的日期和余额衔接结果，包含缺期、重叠、不一致及未检查的原因。

### 按结果增加 待核查流水

控制余额不符时，保留对应文件的交易明细，方便回看原件。

> 💡 工作表表头均为深蓝色并冻结置顶，可以上下滚动不迷路，还自带筛选小按钮。

## ❓ 常见问题

**Q：点"开始整理"没反应，提示"尚未选择文件"？**
👉 你还没选 PDF，先点"选择文件"或"选择文件夹"。

**Q：日志里说"本地读取未通过，且未配置可用的视觉模型"？**
👉 这份 PDF 的格式比较特殊，本地方法认不出来。解决办法：填好模型三件套（接口地址、密码、模型名）再试，人工智能看图通常能搞定。

**Q：为什么有些文件标红了？**
👉 红行的"失败原因"列写得很具体：可能是笔数对不上、金额对不上、余额链条断了，或者所有读取方法都失败了。拿着来源文件名去翻原始 PDF 人工核对一下即可。标红不代表账错了，只代表"机器不敢打包票"，需要人看一眼。👀

**Q：会不会把我原来的 PDF 改掉？**
👉 绝对不会。程序只**读取** PDF，从不修改它们；结果只会写进"提取结果"文件夹里新建的 Excel。🔒

**Q：选文件夹时，为什么没把"提取结果"里的文件算进去？**
👉 程序故意跳过名叫"提取结果"的文件夹，免得把自己生成的文件当输入，越滚越多。

**Q：处理中界面卡住不动了吗？**
👉 没有。读取在后台进行，进度条和日志会实时更新。文件多的时候耐心等即可。
